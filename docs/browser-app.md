# Browser app – plan and builder prompt

Goal: a page where a data manager drops in `rules.xlsx` and the raw export and
gets the findings report – **without any data leaving the browser**.

## Architecture

- Static site (GitHub Pages or Vercel), no backend, no database, no login.
- The checks run in the browser with **Pyodide** (Python compiled to WebAssembly)
  using this repo's `crf_rules` package as a wheel – one engine, already tested,
  no second implementation in JavaScript.
- UI: React + Tailwind (generated by an AI app builder), SheetJS only for
  previewing the Excel sheet.

Screens:
1. Upload: rules sheet + raw export (drag & drop), "Load demo study" button
2. Rule check: table of rules, translated/failed, with the parser's message
3. Results: summary cards, findings table (filter by variable / type / ID),
   chart "findings per variable", download `plausibility_report.xlsx` and `cleaned.csv`
4. "Generated SAS" tab: the program from `generate_sas`, copy/download

## Prompt for v0 / Bolt.new / Lovable

> Build a single-page web app "CRF Rule Engine" with React, TypeScript and
> Tailwind. It must be a fully static, client-side app: no backend, no Supabase,
> no authentication, no network calls except loading Pyodide from its CDN.
> Show a banner "Your data never leaves this browser".
>
> Flow: (1) Upload step with two drop zones: "Rules sheet (.xlsx)" and
> "Raw export (.csv, pipe-delimited)", plus a button "Load demo study" that
> fetches /demo/demo_fu12_rules.xlsx and /demo/demo_fu12_raw.csv.
> (2) After upload, load Pyodide in a Web Worker, install pandas and openpyxl,
> install the wheel /py/crf_rule_engine-0.1.0-py3-none-any.whl with micropip,
> write both files to the Pyodide filesystem and call
> `crf_rules.load_specs`, `crf_rules.read_raw`, `crf_rules.run`.
> Return `result.summary`, `result.errors` and `result.rule_issues` as JSON.
> Show a progress indicator while Pyodide loads.
> (3) Results page with tabs: "Summary" (cards: records, records with findings,
> share in %, format vs. rule findings), "Findings" (sortable, filterable table:
> id, variable, value, type, rule, message), "Rules" (list of rules that could
> not be translated, with reason), "Generated SAS" (output of
> `crf_rules.generate_sas(specs)` in a code block with copy and download).
> Buttons to download the report as .xlsx and the cleaned dataset as .csv,
> both produced in Python via `write_outputs` to the Pyodide filesystem.
> Clean, professional look suitable for clinical data management.

## Which builder

- **v0 (Vercel)** or **Bolt.new**: good for a static React front end, sync to GitHub.
- **Lovable**: also fine, but tends to add a Supabase backend – keep the
  "no backend" sentence in the prompt.
- Alternative without a UI builder: **stlite** (Streamlit running on Pyodide) –
  one Python file, hosted on GitHub Pages; less polished, fastest to build.

Build the wheel for the app: `pip wheel . -w web/public/py --no-deps`
